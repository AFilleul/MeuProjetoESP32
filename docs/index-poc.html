Prova de conceito: ESP-NOW → Wi-Fi → servidor

Para onde a branch com-mini-pc vai agora. A prova de conceito substitui o roteiro MS-006 a MS-009 (o que mudou): primeiro fazer a cadeia inteira rodar do jeito mais direto, depois medir onde ela falha e melhorar em ciclos PDCA. O fluxo detalhado de cada firmware, passo a passo, está em index.html.

Objetivo da prova de conceito

Pergunta a responder: a cadeia nó ESP32 → ESP-NOW → ponte ESP32 → Wi-Fi → roteador → PC entrega as leituras de forma confiável? Se não, onde e por que ela falha, e muda alguma coisa trocar HTTP por MQTT?

Não é o sistema final. É um experimento para descobrir limitações antes de escolher o stack definitivo do gêmeo digital (atualização horária, offline).
Primeiro roda, depois melhora. O ciclo 1 usa o firmware que já existe, sem consertar nada. Cada falha encontrada vira hipótese para o ciclo seguinte.
O resultado é uma tabela de números (entrega %, atraso, recuperação), não "funcionou". É essa tabela que decide se o rádio, o transporte e o banco ficam ou mudam.

Sobre o nome "ponte": é o ESP32 que o código chama de Central (MeuProjetoESP32.ino, EspNowCentral.*). Aqui ele é chamado de ponte porque, nesta branch, só passa as leituras do ESP-NOW para o Wi-Fi.

Comece aqui

O que você precisa ter
  • 2 placas ESP32 com cabo USB: uma para o nó (com o sensor de chuva MH-RD) e uma para a ponte.
  • PC Windows com Arduino IDE e Python 3.12.
  • Acesso ao painel do roteador, para trocar o canal e reservar o IP do PC.
Como trabalhar cada missão
  • As missões chegam pelo app Tarefas-build, com a pasta onde vão as entregas.
  • Ao começar, você escreve as etapas no app: é o seu plano de como fazer.
  • Dúvida ou bloqueio: abra uma pendência no app no mesmo dia.
Por onde ler

Glossário (abra se algum termo for novo)
TermoSignificado
ESP-NOWRádio da Espressif: um ESP32 manda mensagens curtas (até 250 bytes) direto para outro, sem roteador.
BeaconMensagem que a ponte espalha a cada 1,5 s dizendo "estou aqui"; o nó a usa para descobrir o endereço da ponte.
CallbackFunção que o sistema chama sozinho quando algo acontece, por exemplo quando chega um pacote.
TaskTarefa do FreeRTOS: um pedaço do programa que roda em paralelo com o resto, em um dos dois núcleos.
Fila (FreeRTOS)Caixa de passagem de tamanho fixo entre duas tasks: uma coloca, a outra retira.
ACKConfirmação: a resposta "recebi" ou "apliquei" que volta para quem enviou.
Deep sleepSono profundo: o ESP32 desliga quase tudo e recomeça do setup() ao acordar; só a memória RTC é mantida.
Modo ONLINEModo do nó em que ele não dorme e envia no intervalo configurado (usado no cenário de rajada).
RSSIForça do sinal recebido, em dBm. Quanto mais perto de 0, melhor (−50 é ótimo; −90 é limite).
seqNúmero de sequência: cada leitura leva o número seguinte ao anterior. Número que falta é leitura perdida.
p50 / p95Mediana e percentil 95: metade dos valores fica abaixo do p50; 95% ficam abaixo do p95.
MQTT e QoS 1MQTT é um protocolo de mensagens com intermediário (broker; aqui, o Mosquitto). QoS 1 garante entrega pelo menos uma vez.
PDCACiclo de melhoria: planejar, fazer, verificar e agir (padronizar o que funcionou e planejar o próximo ciclo).
Relatório A3Relatório de uma folha (tamanho A3), do método Toyota: problema, causa, dados e recomendação.
Core 0 / core 1Os dois núcleos de processamento da CPU do ESP32. Não confundir com "núcleo operacional".
Mini PCNo código, o PC Windows que roda o servidor (MINI_PC_IP, TaskPushMiniPC).
Núcleo / supérfluoNúcleo operacional é o que a cadeia precisa para funcionar. Supérfluo é o que existe no código mas não serve à prova; fica parado, não é apagado.
